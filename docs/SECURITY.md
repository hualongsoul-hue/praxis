# 安全模型

## 信任边界

用户输入、模型输出、MCP Server、网络响应、技能文件和工具参数均视为不可信。Runtime 配置和宿主
注入的 Provider 属于受信管理面，但仍必须经过严格 Schema 与路径校验。

## 凭据

- 模型密钥只从 `PRAXIS_MODEL_API_KEY` 读取。
- 不把密钥写入 YAML、命令参数、日志、审计、追踪、检查点或异常详情。
- `praxis config show` 输出脱敏配置。
- 已进入 Git 历史的凭据必须在提供方外部轮换；仓库不自动重写或强推历史。

## 工具策略

`ToolPolicy` 是授权与资源边界，不是恶意代码沙箱。文件工具只能访问解析后仍位于授权根目录内的
路径，并拒绝穿越与符号链接逃逸。Shell 默认禁用；启用时仍需审批、受控工作目录、环境变量白名单、
超时和进程树终止。处理不可信命令必须使用容器或 OS 沙箱。

## 网络

自主网络工具只接受 HTTP/HTTPS，拒绝 URL 凭据，并对每次重定向重新解析 DNS 与地址。默认阻止
loopback、私网、链路本地和非全局地址，同时流式限制响应大小。模型网关的受信私有 API Base 不会
放宽 Agent 网络工具的策略。

## 审批与重试

审批处理器缺失、超时、异常或返回无效结果时一律拒绝。自动重试只适用于只读或显式幂等工具。
模型流已经产生任何输出后不重新调用，避免重复文本和工具执行。

## 数据完整性

检查点包含 schema version 与校验和，审计事件采用 append-only 键。文件写入使用临时文件、冲刷和
原子替换。损坏、未知版本或冲突会显式失败。

漏洞报告流程见仓库根目录 [SECURITY.md](../SECURITY.md)。
