# 2026-09-10 设计与实现复审

审查基线：`8315497`，当前 `dev` 分支。检查配置到 Runtime 的接线、资源所有权、
上下文协议、工具执行边界与可观测性；静态引用结果仅作为候选，不能把 SDK 公共接口
或框架回调误判为死代码。

## 已确认问题与修复范围

1. 会话、子代理创建与 Runtime 关闭存在竞态，重复进入可创建多个底层会话；关闭后的句柄仍可进入。
2. 会话扩展装配失败时，已启动的记忆任务没有回滚；工厂在其他组件构造前提前启动记忆。
3. 记忆关闭中任一步失败会跳过后续资源关闭。
4. 压缩按单条消息保留关键词，可能拆开 assistant/tool 消息组；保留文件数量为零时切片错误，空摘要会丢失原始消息。
5. 输入护栏之前写入记忆，拒绝的输入仍可能进入后台提取。
6. JIT 检索只能通过底层工厂注入，标准 Runtime 路径无法启用。
7. 配置的追踪导出器未用于真实模型调用和工具调用；禁用追踪仍可能使用宿主 tracer。
8. 文件预检后的读取没有硬字节上限，文件增长可突破内存约束。
9. 流式关闭持有执行锁并取消消费方任务，可能死锁或取消宿主请求处理器；嵌套生成器未及时关闭。最终采用单生产任务与有界按需事件通道，保留适配器上下文，并发关闭共同等待同一次清理。
10. 权限配置忽略未知字段并接受错误裁决，类别规则可能先于具体工具拒绝规则放行；现在严格验证并按明确优先级匹配。
11. 不同会话及子代理共享可变护栏，临时授权和动态规则相互泄漏；现在只共享不可变策略，各自隔离可变状态。
12. 技能声明的工具依赖检查未接入激活流程；多脚本注册失败会留下前面已注册的工具。现在依赖与整批脚本均通过校验后才激活。
13. 模型适配器同步创建流失败时没有结束 span；流创建、迭代、取消和关闭统一清理，异常仅记录类型。
14. 默认 Router → chat_stream → LiteLLM Provider 的关闭链缺失。现在逐层显式等待关闭，Provider 清理完成前保持并发槽占用，预算结算在退出时执行。自然耗尽与主动关闭同时发生时，底层关闭任务受取消保护，并在原 Context 中恢复关联信息；通用源生成器仍保持原生产任务亲和性。
15. wheel 冒烟只校验了导入和存储，没有实际运行完整 SDK；Windows 文本子进程的解码线程异常还可能被误判为成功。现在执行安装后 Runtime 的非流式、流式、健康与关闭流程，强制隔离解释器使用 UTF-8，并在主线程严格解码输出，错误必须使门禁失败。

## 验证方式

针对每项行为先构造回归：事件同步控制并发、真实后台任务检查回收、协议完整性检查、
模型网关边界记录实际 Prompt、内存 span exporter 验证真实调用、受控文件增长测试。
完成后运行 Ruff、Pyright strict、全量严格测试与分支覆盖、依赖审计、构建和 wheel 冒烟；
推送后核查 Windows/Linux 与 Python 3.12/3.13/3.14 CI。

## 死代码处理原则

公开扩展 API、Pydantic 校验器、HTTP handler、LiteLLM 回调即使没有普通直接调用也不是死代码。
确认与现用实现重复、没有生产调用的内部逻辑才删除；需要的未接线能力应补齐集成。

本轮删除 `ContextCompactor.strip_tool_outputs`：生产路径已经使用 `ObservationMasker`，该方法只有
自证式单元测试而无生产调用。同步删除重复测试，新增基于完整工具调用协议的压缩回归。
JIT、追踪和技能依赖检查属于设计需要但未接线的功能，已接入运行路径并验证实际 Prompt、span、
技能状态和工具注册结果，而不是仅断言某个模拟方法被调用。
另移除了跨组件测试中强制共享原始护栏对象的身份断言，改为校验实际工具裁决和隔离后的内部接线。
独立复审指出的并发 `aclose`、逐次切换生产任务的 ContextVar 回归以及 Provider 清理缺口均先用
受控异步清理与真实 Router 包装链复现，再实施修复。
